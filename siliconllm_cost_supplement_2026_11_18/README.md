## R(k) 的解释

截图中的解释适用于旧snapshot/restore/replay路径。假设草稿A B C D在C处拒绝，接受了A B：

1. 恢复验证前的KV cache。
2. 普通输入x，预测A。
3. 普通输入A，预测B。
4. 普通输入B，预测Z，替代C。

重放包含三次模型前向，按18.90 ms每步估计，**这次拒绝的重放前向成本为56.70 ms**。Z下一次正常处理不再计为另一次恢复重放。快照恢复等额外操作若有耗时，也不能在最终wall time里漏掉。

而R(k)是对各个拒绝位置加权的每轮期望，不是上面这一次拒绝的耗时：

```text
R(k) = 18.90 * sum((j+1) * p^j * (1-p), j=0..k-1)
```

当p=0.98、k=8，得到R(8)=12.3935746 ms，显示为12.39 ms。它小于56.70并不矛盾，因为很多轮可能全部接受，而本算例假设全接受没有额外replay。上面四个草稿符号说明的是j=2分支；另一个期望值计算使用k=8，PPT备注已区分。

假设匹配概率恒定且独立、不发生EOS或预算截断、拒绝后确实重放j+1步，这个公式才是当前算例的近似。native trim路径不能套三次模型前向的成本。

## C(k) 的解释

假设L=0.02乘18.90，即0.378 ms；G(k)=1+p+...+p^k。

```text
C(k) = [V(k) + L + R(k)] / G(k)
C(8) = (27.97 + 0.38 + 12.39) / 8.31 = approximately 4.90 ms/token
```

| k | V(k)，ms | L，ms | R(k)，ms | G(k)，token | C(k)，ms/token |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0 | 18.90 | 0.00 | 0.00 | 1.00 | 18.90 |
| 2 | 20.79 | 0.38 | 1.12 | 2.94 | 7.58 |
| 4 | 23.06 | 0.38 | 3.63 | 4.80 | 5.63 |
| 8 | 27.97 | 0.38 | 12.39 | 8.31 | 4.90 |
| 16 | 38.75 | 0.38 | 42.13 | 14.53 | 5.59 |

k=8分数最低，也低于普通参考的95%成本，因而这个假设算例会选8。k=0是单独的普通参考，没有草稿查找和replay；不能把这一行当作已执行查找的fallback完整计时。

内部计算用未舍入输入，表格和口头算式只显示两位。38.745按十进制四舍五入显示为38.75。4.90 ms/token是模型分数，不是实测平均延迟，不直接形成新的性能结论。

## 简短讲法

可以这样向老师解释：

> V(k)描述一次批量验证要花多少时间。R(k)描述这条replay实现中拒绝后可能增加的预期成本。C(k)把一轮预计总时间除以预计输出token数，比较不同草稿长度。这里用18.90 ms作为历史标尺，其余输入是说明假设，不是新测量。算例中k=8的单位token分数最低，因此选择8。如果改用native trim，就需要按实际裁剪成本更新R(k)，再重新比较。
